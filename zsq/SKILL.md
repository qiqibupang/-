# 用户习惯

默认按下面的偏好和用户协作；如果用户在当前请求里明确提出新要求，以当前请求为准。

## 回复方式

- 用简体中文，先说结论；篇幅按问题复杂度决定，不要刻意写得过短，也不展开无关背景。
- 解释代码时说人话，注释和说明口语化、自然，不要有明显的 AI 腔。
- 不重复用户已经知道的内容，也不要用过多标题和列表。

## 验证习惯

- 按改动风险做一次简单、聚焦的验证；不要为小改动投入大量时间反复编译、运行、检查蓝图或截图。
- 用户明确要求不验证时，直接遵守；没有验证就如实说明，不把推测说成已经确认。

## 工具选择

- 当工具调用能直接完成任务或显著提高准确性，并且已在授权范围内时，选择最合适的可用工具。上下文已足够时直接交付；工具降级只在会影响结果时说明。
- 不得编造工具调用结果；平台和工具明确要求的权限仍须遵守。

## 代码习惯

- 优先使用简单、直观、容易维护的架构，不为了兼容边缘情况加入复杂封装或自定义 Thunk。
- 先沿用项目现有写法，修改范围保持小，不做无关重构。
- 围绕用户目标实现必要逻辑；可自行增加完成需求必需的函数、变量和注释，无须逐项确认。不要顺手增加无关功能或重构；影响较大的实现选择简要说明理由。
- Unreal C++ 遍历数组默认使用下标写法；当前要求或项目约定不同时按其执行：`for (int32 Index = 0; Index < Array.Num(); ++Index)`。
- Unreal 项目中，蓝图和 C++ 按整体架构协作：C++ 负责核心逻辑和数据，蓝图负责派生、配置和流程编排；变量优先定义在 C++ 父类里。
- Unreal C++ 的 `UPROPERTY` 和 `UFUNCTION` 默认不添加 `Category`，除非用户特别要求。

## Cocos Google 试玩构建（仅在条件满足时启用）

仅当当前项目已明确是 Cocos，且用户当前指令或未撤销的上下文明确是 Google 试玩广告的构建、打包或包体压缩时，才执行本节。已确认这两个事实后的「继续构建」「继续优化」等后续指令直接适用，不重复询问。普通 Cocos 项目、其他广告渠道和与试玩无关的任务不适用；用户当前指令另有要求时以其为准。

本节优先于上方的通用验证习惯：用户明确要求不验证时不验证；其他情况下只做下列包体与运行验收，不自行追加控制台、资源路径、网络或其他 Cocos 构建验证。

- 大多数此类项目使用 Cocos SuperHTML 扩展构建。项目使用或产出 SuperHTML 时，以扩展实际打包规则和文件结构为准，按上方默认五个渠道或用户明确指定的渠道生成产物。不因 Google 验收标准而改成仅构建 Google，也不删除已有的其他渠道产物。
- 允许用脚本优化体积，优先处理图片。先尝试 WebP 等更小格式，以及图片显示尺寸、质量和 HTML 内嵌图片；只在产物实际变小且后续运行验收通过时保留处理结果。图片优化仍不足时，再处理其他已确认的体积来源。
- 体积验收对象是 SuperHTML 文件夹中的 Google 渠道压缩包解压后的 HTML 文件。第一步确认该 HTML 文件不超过 **5,000,000 B（5 MB）**，并报告实际字节数及剩余或超出的字节数。不能用 ZIP 压缩后的大小代替 HTML 解压后的大小；这是验收标准，不是构建渠道范围限制。未通过时不做运行验收。
- SuperHTML 正常产物解压后若只有一个 HTML 文件，就保留单 HTML 结构，不拆分文件、不外链资源，也不调整目录结构。
- 第二步在包体通过后实际运行入口 HTML，并进入游戏关卡或可交互的实际游戏内容。合理启动期后仍黑屏、长期停留在插屏界面，或无法进入游戏内容时视为验收失败。包体与运行两步都通过才算完成。
