# Unreal C++ 与蓝图协作

涉及 UE 项目的设计、写代码、评审时启用本章；用户当前要求优先。默认项目是 C++ 项目、逻辑封装在 `Plugins/<插件>/Source/` 下的 Runtime 模块。目标是让用户高效迭代：AI 负责 C++ 规则和引擎原生系统之间的胶水，用户在编辑器里做资产、蓝图子类、表现和调参；两边并行，每轮都是一个能在 PIE 里立刻看到的小增量。

## UE 项目默认接入 UE-MCP

- 用户已指定：后续 UE 项目默认接入第三方 **db-lyon/ue-mcp**，编辑器操作优先使用这套 MCP；不要把名称相似的其他 Unreal MCP 项目当成同一个工具。
- 官方网站与下载入口（用户指定）：[https://ue-mcp.com/](https://ue-mcp.com/)。
- 补充来源：仓库与源码下载 [https://github.com/db-lyon/ue-mcp](https://github.com/db-lyon/ue-mcp)；发行版本：[Releases](https://github.com/db-lyon/ue-mcp/releases)；npm 包：[ue-mcp](https://www.npmjs.com/package/ue-mcp)。工程内的桥接插件名为 `UE_MCP_Bridge`。
- 开始 UE 项目工作时先检查已有连接及其 `.uproject` 目标。已接入就复用；未接入时，按仓库当前说明和项目引擎版本完成接入，无需重复询问是否使用此 MCP。常规入口是在项目目录运行 `npx ue-mcp init`；MCP 服务启动参数指向当前项目的 `.uproject`，不沿用其他工程的路径或端口。接入前保留已有配置，避免覆盖其他 MCP 服务。
- 接入后用 `project(action="get_status")` 确认连接的是当前工程，按需用 `catalog` 查询动作参数。工具前缀可能随客户端配置变化，不固定为某一个 UE 版本名。
- UE 5.8 及以上可通过这套 MCP 的 `epic_*` 动作调用 Epic 官方工具；第三方桥接和官方工具可以配合使用。C++ 文件修改与 UBT 编译仍按实际需要使用本地文件和命令行工具。
- 已正常工作的安装不因日常任务自动升级；需要升级时参考仓库的 `npx ue-mcp update` 流程，并核对服务端、桥接插件与引擎兼容性。接入偏好不改变用户对资产修改、游戏运行或测试的限制。

## 原生优先

- 先找 UE 官方原生系统，能用原生就不自己写：粒子、碎块、拖尾用 Niagara；物理破坏用 Chaos 几何集合；输入用 Enhanced Input；配置用 DataTable / `UPrimaryDataAsset`；UI 用 UMG；少量主角物件的时间轴表现用 Timeline / Curve；动画事件用 AnimNotify；材质反馈用材质参数 + MID；音效用 MetaSound / SoundCue；相机用 CameraShake / SpringArm；AI 用行为树 / StateTree；保存用 SaveGame。
- 判断顺序：引擎有现成系统 → 直接用并由 C++ 暴露参数和钩子；引擎只有零件 → C++ 拼接零件；确实没有 → 才手写模拟或算法。开工前用一句话说明选了哪个原生系统、为什么。
- 不用脚本、无头编辑器或反射接口批量生成特效、材质、动画等美术类资产，除非用户明确要求；这类资产用户从模板在编辑器里几分钟就能建好，AI 只给模板名、要改的模块和参数值。

## 分层原则

- **C++ 放**：变量和数据结构、生成与批量逻辑、数组与格位管理、定时器、样条与曲线运动的计算、对象池、伤害与收集等规则、状态机、接口定义、GameplayTag 判定、原生系统的参数传递与钩子调用。判断标准：改完能用编译器、日志或自动化测试判对错的放 C++。
- **蓝图放**：网格、材质、特效、音效、UI 资源指定；时间轴驱动的表现（闪白、缩放、抛物弧的视觉）；关卡里的摆放和参数微调；数据资产填值；在钩子里连表现。判断标准：必须看着屏幕反复调的放蓝图。
- **直接交给用户做**：在编辑器里点几下就能完成的事，如建蓝图子类、从模板建 Niagara/材质/动画蓝图、拖引用、摆关卡、填数据表。AI 给精确步骤、资产名和参数值，不替用户用工具绕路完成。判断标准：编辑器操作快于写代码加编译的放这里。
- 变量一律定义在 C++ 父类，蓝图不新建变量；蓝图里出现需要跨对象读取的状态，就是该搬进 C++ 的信号。C++ 不反向依赖蓝图（不 `FindFunction`、不 `LoadClass` 硬编码蓝图路径），确需引用蓝图类或资产时用 `TSubclassOf<>`、`TSoftClassPtr<>`、`TObjectPtr<UNiagaraSystem>` 等暴露成属性让蓝图或数据资产填。
- AI 默认不画蓝图节点图。用户要求时，或者钩子里的逻辑只有三五个节点时，用文字按顺序描述"哪个事件 → 哪个节点 → 接什么引脚"。

## 每轮迭代的节奏

- **开工前**先给一段「本轮分工」：C++ 我改哪几个类、新增或修改哪些暴露属性和钩子；你在编辑器里可以同时准备什么（建哪个子类、准备哪些网格/材质/Niagara/音效、在关卡里摆什么）；需要你确认的资产名或参数口径。让用户在 AI 写代码和编译期间不闲着。
- **收工后**给「编辑器操作清单」：打开哪个蓝图或资产、填哪几个值、在哪个钩子事件里连什么表现；然后给验证方式：在 PIE 里做什么操作、期待看到什么。表现类结果由用户在 PIE 里看，AI 只验证编译通过和逻辑正确，不用无头脚本反复验证视觉效果。
- 一轮只做一个能在 PIE 里试出来的小增量。可调数值一律暴露成 `UPROPERTY` 并给合理默认值，让用户调参不用等重新编译；表现全部走钩子，让用户改表现不用碰 C++。
- 用户反馈"效果不对"时，先判断是参数问题（让用户在编辑器里调）还是逻辑问题（AI 改 C++），不默认重写代码。

## 编译与编辑器

- 编辑器开着时，AI 改完 C++ 只做编译检查或 Live Coding 能吃下的改动：只改 `.cpp` 函数体时提示用户按 Live Coding（Ctrl+Alt+F11）；改了头文件里的 `UPROPERTY`、`UFUNCTION`、类成员或构造函数时，说明 Live Coding 可能不生效、需要关编辑器重新编译或从 IDE 编译。
- 用 UBT 编译遇到 DLL 被编辑器占用，直接告知用户关闭编辑器后重编，不改名、不删除、不绕过文件锁。
- 交付时说明编译结果和用户下一步是"直接 Live Coding"还是"重启编辑器"。

## 类的拆分

- 一个玩法拆成三类基类：**生成器**（`ASpawnerBase`：摆放、批量生成、持有实例数组、格位查询）、**单体**（自身状态与响应）、**管理器或组件**（跨对象规则用 `UActorComponent`，全局唯一的用 `UWorldSubsystem` / `UGameInstanceSubsystem`）。不把整套逻辑塞进一个类，也不做全局状态机。
- GameMode、PlayerController 只放输入和必须全局协调的事。关卡流程由关卡序列或管理器驱动，不用 LevelScript。
- 变体靠蓝图子类改资源和默认值；行为差异大到要写代码时才建 C++ 子类。
- 可复用的发射物、掉落物用对象池组件：预生成、"正在使用"标记、取用/回归；消失优先隐藏 + 关碰撞，不销毁。

## 暴露给蓝图的方式

- 配置项 `UPROPERTY(EditAnywhere, BlueprintReadWrite)`；只在类默认值里改的用 `EditDefaultsOnly`，只在关卡实例改的用 `EditInstanceOnly`；运行时状态 `VisibleAnywhere, BlueprintReadOnly`；生成时要传入的加 `ExposeOnSpawn`，配合 `SpawnActorDeferred` 在 `FinishSpawning` 前赋值。
- 组件在构造函数里 `CreateDefaultSubobject`，标 `VisibleAnywhere, BlueprintReadOnly`，命名按用途（`HitBox`、`DetectRange`、`MeshComp`），根组件用 `SceneRoot`。
- 逻辑函数 `BlueprintCallable`，纯查询 `BlueprintPure`（`const`）。
- 表现钩子用 `BlueprintImplementableEvent`（C++ 无实现）或 `BlueprintNativeEvent`（C++ 有默认实现，蓝图可覆盖并可调父类）。钩子命名 `On动词`，成对出现：`OnLaunched/OnStopped`、`OnAcquired/OnReleased`、`OnHit/OnDied`。C++ 在状态变化处调钩子，蓝图在钩子里连时间轴、粒子、音效。
- 事件分发器只在确需一对多通知时用 `DECLARE_DYNAMIC_MULTICAST_DELEGATE` + `BlueprintAssignable`；点对点通知走接口。
- 暴露到编辑器或蓝图的 `UPROPERTY` 必须用 `DisplayName` 显示中文，不设置 `Category`；常用配置用较小且连续的 `DisplayPriority` 靠前显示，运行时状态排后。
- 暴露到蓝图的 `UFUNCTION` 必须设置中文 `DisplayName`，并按蓝图节点类型添加前缀：普通函数和纯函数使用 `F_中文名`，自定义事件使用 `CE_中文名`。以蓝图中的实际节点形态为准；带返回值的 `BlueprintNativeEvent` 属于函数，使用 `F_`。C++ 函数名仍使用英文 PascalCase。

## 默认值一致性

- Actor/Component 在游戏里应该保持的默认状态（碰撞响应、Tick 开关、可见性、Overlap/Hit 事件开关等），直接在构造函数里设成这个值；不允许在 `BeginPlay` 或其他运行时函数里，把编辑器/蓝图能看到的默认值悄悄改写成另一个值当作"最终状态"——蓝图 Class Defaults 里看到的必须就是游戏跑起来的实际值，不能"编辑器一个样，运行时另一个样"让人靠猜。
- 确实需要状态随时机切换（比如开局前仅查询、开局后阻挡），封装成命名清楚的函数（如 `EnterGameplayCollision()`），在对应 `UPROPERTY` 旁用注释标注"运行时会被 XxxFunc 改为 Block，见 XxxFunc"；交付清单里专门列出本次新增或修改的、运行时会覆盖蓝图默认值的属性和触发时机，不能让用户只看蓝图判断不出运行时行为。
- 新写或评审 C++ 时主动检查：新建 Actor/Component 蓝图子类的 Class Defaults，是否等于代码运行后的实际值；不等于就必须按上一条标注清楚，不允许无注释的静默覆盖。

## 蓝图事件与子蓝图协作

- 当前及后续 UE 逻辑开发，都要审查本次涉及的玩法流程，主动识别可帮助用户迭代、接表现或做小功能的事件：攻击开始/出手/结束、伤害/死亡、生成/回收、交互结果、状态切换等。沿用 UE 原生事件；已有原生入口足够时直接说明，不再复制一层。
- 交付候选事件时列出中文名称、所属类、触发时机、参数和用途，并单列明显低价值、重复或高频事件，让用户决定是否暴露；不为凑数量把每个内部函数或每帧计算都暴露成事件。
- 询问用户是否将选定事件自动添加到其已建立的子蓝图事件图。用户已要求添加全部或指定一批时直接执行，不逐项重复询问；只有尚未确定的事件范围或子蓝图目标才继续澄清。等待答案时继续完成不依赖答案的 C++ 工作。
- 获得添加节点授权后，先确认目标蓝图和继承关系，备份受影响资源；在现有事件图的空白区域分组摆出继承事件节点并加用途注释。已有事件、连线和布局不移动、不覆盖，重复运行不重复添加；不要创建同名普通 Custom Event 冒充父类事件重写。组件分发器使用绑定事件节点。
- 父类已有蓝图实现或 BlueprintNativeEvent 默认逻辑时，新节点必须正确连接父类调用与参数，防止空重写吞掉伤害、特效或 UI 逻辑。已有节点保持用户原本的调用方式；事件状态先提交再通知蓝图，检查销毁、重入及对象池复用的影响。
- 写入磁盘资源前避免覆盖编辑器未保存修改；优先在当前编辑器内事务式编辑，离线批处理则先由用户保存并关闭编辑器。反射头文件变更后完整编译；逐个编译受影响蓝图，重新加载核查节点、父类调用和幂等性，交付事件清单、资源路径和实际验证结果。

## 类型与通信

- 结构体 `USTRUCT(BlueprintType)` 定义在 C++，成员 `UPROPERTY(EditAnywhere, BlueprintReadWrite)`；多个类共用的一组参数（如发射配置）打包成一个结构体传，不散成多个变量。需要多套配置时升级为 `UPrimaryDataAsset` 子类，蓝图侧建 `DA_` 资产填值。
- 枚举 `UENUM(BlueprintType) enum class : uint8`，只用于单个类内部的模式开关；阵营、类型、状态跨对象表达用 `FGameplayTag`，标签集中定义在数据表或 `UGameplayTagsManager` 原生注册，按层级用 `MatchesTag` / `HasTag` 判定。
- 对象间响应用接口：`UINTERFACE(Blueprintable)`，函数标 `BlueprintNativeEvent`，调用方用 `IXxx::Execute_Func(Target, ...)`，先 `Target->Implements<UXxx>()` 判定；不 `Cast<IXxx>`（蓝图实现者会拿到空）。接口按职责域拆（伤害交互、收集运输、生命周期通知），每个不超过五六个函数。
- 引用来源：生成时保存、碰撞事件的 `OtherActor`、`EditInstanceOnly` 让关卡手填。不用 `GetAllActorsOfClass`。手填引用在 `BeginPlay` 判空并 `UE_LOG` Warning，不静默跳过。
- 触发源以组件的 `OnComponentBeginOverlap/EndOverlap` 为主，`OnComponentHit` 只用于物理表现。

## 运行时行为

- 周期逻辑用 `FTimerHandle` + `SetTimer`，间隔固定的 `bLoop=true`，间隔可变的非循环、回调末尾按当前值重设；`EndPlay` 里 `ClearTimer`。Tick 只用于真正连续的事（跟随、沿样条移动），默认 `PrimaryActorTick.bCanEverTick=false`，需要时按状态 `SetActorTickEnabled`。
- 大量同类单体的动画不各自跑时间轴：由管理器统一插值、或 `UInstancedStaticMeshComponent` 加材质参数、或 VAT。时间轴留给数量少的主角物件，放蓝图。
- 样条移动维护"沿样条距离"按速度累加，`GetLocationAtDistanceAlongSpline` 取位置和旋转；曲线运动（贝塞尔、抛物线、环绕）封装成 `UFUNCTION(BlueprintPure)` 静态函数放函数库 `UBlueprintFunctionLibrary` 子类。
- 材质反馈用 `UMaterialInstanceDynamic`，在 `BeginPlay` 创建一次缓存，钩子里改参数。
- 物理只用于破坏表现，用 Chaos 几何集合 + 精简的自定义力场 Actor，不复制引擎示例；碎块、飞溅等表现走 Niagara，C++ 只负责 `SpawnSystemAtLocation` 和设置 `User.` 参数。
- 生命周期：重写 `BeginPlay` / `EndPlay` / `OnConstruction` 必调 `Super::`；预览用 `OnConstruction` 里的 Child Actor 或 ISM，运行时统一 Spawn 存数组，预览物在 `BeginPlay` 销毁或隐藏。

## 命名

- C++ 类按引擎前缀：`A` Actor、`U` 对象/组件、`F` 结构体、`E` 枚举、`I` 接口；成员和函数英文 PascalCase，布尔 `bXxx`，数组复数或 `XxxArray`。
- 蓝图侧资产：`BP_`、`AC_`、`WBP_`、`DA_`、`E_`、`ST_`、`BI_` + 中文，子类 `_Child`；蓝图子类名和 C++ 父类一一对应（`ABulletBase` → `BP_子弹`）。这是给用户和组内蓝图使用者看的，C++ 里不出现中文标识符。
- 数组遍历 `for (int32 Index = 0; Index < Array.Num(); ++Index)`；项目约定不同时按项目。

## 发布与迭代

- 逻辑封装为插件：`.uplugin` 里模块 `Type="Runtime"`、`LoadingPhase="Default"`，编辑器工具单独 `Type="Editor"` 模块；`EngineVersion` 写死当前版本；示例资源放插件自己的 `Content/`。
- 给纯蓝图用户的发行版用 `RunUAT.bat BuildPlugin -Plugin=... -Package=... -TargetPlatforms=Win64 -Rocket` 产出，附 Binaries，不要求对方装 VS。开发在含 Source 的项目里进行，Live Coding 验证。
- 已发布的 `UPROPERTY` 只加不删；改名必须在 `DefaultEngine.ini` 加 `CoreRedirects`；改父类结构后提醒用户检查已有蓝图子类。
- 交付时列：选用的原生系统及理由（一行）、新增/修改的类与文件、暴露给蓝图的属性和钩子、编辑器操作清单（建哪个子类、填哪些值、在哪个事件里连表现）、PIE 验证方式、编译结果与下一步（Live Coding 还是重启编辑器）。

## Cocos 脚本与预制体规范

以下规则只要当前项目是 Cocos 项目，就适用于所有新增和修改的脚本逻辑：

- 脚本组件能放在预制体父节点时，统一挂在父节点。父节点只承担预制体身份、脚本和整体变换，不放 Sprite、Label、碰撞体、刚体等表现或物理组件。
- Sprite、Label、RigidBody2D、Collider2D 以及其他表现和物理组件统一放在父节点的子节点下；子节点按职责命名。脚本需要控制整体对象时，通过暴露引用绑定父节点，移动、隐藏、销毁都作用于父节点。
- 暴露引用是预制体契约，不写“缺失时改用脚本节点”“缺失时跳过”“缺失时创建默认对象”等兜底游戏逻辑。必填引用直接使用；预制体和场景交付前检查引用完整。运行时对象已经销毁、停用等状态判断属于正常生命周期处理，可以保留。
- 所有对编辑器暴露的属性使用中文 displayName；脚本类使用中文 @ccclass(中文脚本名)，让组件和属性在编辑器中显示中文。代码内部标识符按项目既有命名保持一致，不能用内部英文名代替外部显示名。
- 预制体结构、脚本挂载位置、子节点职责和必填引用在交付时一起校验；发现父节点存在 Sprite、Label 或碰撞体时，优先调整预制体结构，不在脚本里增加兼容分支。

## 体积红线

- Google 渠道压缩包解压后的全部文件总字节数（单 HTML 结构时即该 HTML 的字节数）：硬上限 **5,000,000 B**，任何情况不得超过；交付目标 **≤ 4,500,000 B**，余量不足 250,000 B 继续优化。
- 按十进制字节比较，不能用 ZIP 压缩后大小代替解压后大小。报告时给实际字节数和剩余/超出字节数。
- 这是 Google 渠道的验收标准，不是构建范围限制：其他渠道仍按项目配置正常生成，不因 Google 超限而只构建 Google 或删除其他渠道产物。

## Cocos 构建与优化落层

- 构建与压缩不得删减任何已经使用的内容或功能，包括人物、骨骼、动画片段及动作状态、特效、音频、贴图、场景和交互逻辑。人物原有动画必须保留并正常播放，不得通过删除动画、停用功能、移除运行时所需资源或排除出包来达成体积目标；只能在保留原有内容、功能和表现的前提下优化存储、编码、压缩及资源复用。
- 清理资源前必须确认其确实未被使用，同时检查场景、预制体、材质、动画、代码及动态加载路径；静态引用未检出、当前关卡未出现或文件名含 `_备份` 都不能作为删除依据。用途不确定就保留。优化后针对受影响内容验证其仍可加载、播放和触发，不能用包体达标代替内容完整性验收。
- 项目使用 SuperHTML 扩展时，以扩展实际打包规则和文件结构为准。Google 采用单 HTML 还是多文件 ZIP，沿用项目当前 SuperHTML 配置和渠道现行规则，不自行切换结构、不拆分或外链资源。
- 超限时进入"统计体积来源 → 优化 → 重新构建 → 解压测量"迭代，依据每轮实际字节数决定下一步，直到达标；不停在一次尝试，无收益的方案及时更换。优化须保留玩法、必要内容和商店跳转，不能靠删验收要求凑体积。
- 优化优先落到源工程或 Cocos 构建配置：`assets/` 源图转 WebP 等更小格式并替换引用、按实际显示尺寸缩图、降低图片运行时内存和显存占用（如降低纹理分辨率、采用目标平台支持的 GPU 压缩纹理格式、按需调整 mipmap）、清理经核实确实未使用的资源、音频降码率、构建配置设纹理压缩预设。图片内存优化也是有效的优化方式，但 WebP 等文件压缩不代表解码后的内存同步下降；分别实测包体与内存收益，保留必要画质和平台兼容性，内存下降不能替代包体达标。目标是用户之后手动从编辑器或一键脚本构建也直接达标。
- 只对 `build/` 产物做后处理（node 脚本转 WebP、去重内联库）而源工程未改，属于兜底，不算完成优化；若必须依赖后处理，要接进用户的一键 bat 或 Cocos 构建钩子，不得交付需要用户额外记住手动运行的脚本。重复内联的公共库（如多份 jszip）在 SuperHTML 或构建配置层面修根因。
- 交付时注明每项优化落在源工程、构建配置还是后处理，并报告三个数字：源资源图片总字节数、`build/web-mobile` 原始产物字节数、最终 Google 产物字节数。前两个没变小就是没落到源头。
- "重新构建"指实际执行 Cocos Creator 命令行构建（`CocosCreator.exe --project <项目> --build "configPath=<配置>"`，3.8 成功退出码 36）或从头跑用户的一键脚本，并核对产物 mtime 晚于本次构建开始时间；对旧 `build/` 直接跑后处理不算。交付时给出构建命令、退出码、产物时间戳。
- 优化完成后删除或移走旧 `build/`，按用户平时的手动方式干净构建一次并测量，以此作为验收依据，不用中间产物代替。

## 运行与商店跳转验收

- 体积达标后才进入正式运行验收（定位压缩导致的问题可做必要运行诊断）。实际运行入口 HTML 并进入关卡或可交互的游戏内容；合理启动期后仍黑屏、停在插屏、进不了游戏即失败。后续修复改变 Google 产物时重新测体积。
- 每个渠道分别运行最终 HTML（ZIP 先解压）做一次简洁的商店跳转验证，不以一个渠道代表其他渠道。先定位工程里的跳转按钮或商店逻辑，在成品中点击该按钮（不便点击时调用同一游戏入口），确认完整调用链进入当前渠道的跳转接口并指向配置的商店或由渠道 SDK 接管；不能只查链接字符串或绕过游戏逻辑直接调 SDK。
- 按实际渠道接口验证（如 AppLovin 的 MRAID），浏览器 `window.open` 成功不算通过。优先用渠道测试环境；不可用时可模拟 SDK 并记录收到的调用和目标，标注"接口模拟通过，平台实机未验证"，模拟结果只用于排查，不能据此判定通过或允许交付。
- 简要记录各渠道触发入口、调用接口、目标、结果。发现失效先修复并重新生成受影响成品再针对性复验，不扩大为全量测试。
